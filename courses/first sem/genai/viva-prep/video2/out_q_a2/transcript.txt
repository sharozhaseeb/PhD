[22:10] Q4 · The reverse step, symbol by symbol
Let us read the formula from the inside out. x t is the current noisy image. Epsilon theta of x t and t is the U-Net's guess of the noise in it. The theta says it is learned. The fraction, beta t over the square root of one minus alpha bar t, says how much of that guessed noise to remove at this one step. It is small, so each step removes only a slice. Why add noise while removing noise? It keeps the sampler random, so it draws from the whole distribution instead of collapsing to one average image. At the very last step, t equals zero, we add no noise. The last line is x hat zero, the model's guess of the clean image: the closed form solved backwards for x zero, using the guessed noise.

[34:51] Q5 · Wrong t, skipped steps, and the DDIM idea
What goes wrong if you pass the wrong t? Say the image is very noisy, but you tell the network t equals 100. The network expects only a little noise, so its guess is scaled for the wrong level, and the coefficients you read at step 100 are also wrong for this image. Noise is left behind, or too much is removed, and the samples come out noisy or washed out. What about skipping steps? Each DDPM update is derived for exactly one step, from t to t minus one. It removes only that one step's slice of noise, beta t over root of one minus alpha bar t. If you jump from 999 straight to 989 with the same formula, you remove one step's worth of noise but claim ten, so most of the noise stays in. To skip steps correctly you need a sampler designed for it. DDIM, from Song and colleagues in 2021, reuses the same trained noise network, but uses x hat zero to jump directly to an earlier step, so fifty steps can replace a thousand, with no retraining. With its noise setting, eta, at zero, the usual choice, it adds no fresh noise at all, so it is deterministic: the same starting noise always gives the same image. Say clearly that we did not run any of this. Our sampler is plain DDPM, all 1000 steps.

[58:51] Q8 · ViT: 16 × 16 patches and global attention
First ViT. On the left of the diagram is the 224 by 224 image. It is cut into 16 by 16 pixel patches. 224 over 16 is 14, so there are 14 by 14, which is 196 patches. Each patch becomes one token, a vector of 768 numbers. In front, one extra learned token is added, called CLS, short for classification. Through attention it collects a summary of the whole image. That makes 197 tokens, and learned position embeddings tell the model where each patch came from. Then twelve transformer blocks. In each block, every token attends to every other token. That is global attention. It is powerful, because any patch can use information from anywhere in the image right away. But it has a price. The number of token pairs is the number of tokens squared, so the cost grows quadratically with the number of tokens. Double the image side, and there are four times the tokens and sixteen times the attention pairs. And notice the shape. It stays 197 by 768 in every block. ViT works at one single scale, stride 16, from the first block to the last.

[60:16] Q8 · Swin: windows, shifted windows, and four stages
Now Swin. Patch partition cuts the image into small 4 by 4 patches, so a 224 image gives 56 by 56 tokens, each 96 numbers wide. Inside each stage, attention only happens inside 7 by 7 windows, the boxes on the grid. Each token only looks at the 49 tokens in its own window. That alone would trap information inside each window. So every second block shifts the windows by three tokens, about half a window. Now tokens that sat on a border share a window with their neighbours, and information can flow across the whole image over several blocks. Blocks therefore come in pairs: a window block, then a shifted window block. In timm's Swin tiny, stage four is a single 7 by 7 window, so there is no shift there. At the start of stages two, three and four, patch merging joins each 2 by 2 group of neighbours, so the grid halves and the channels double. It is a concatenation and a linear layer, not pooling. The result is hierarchical: 56, 28, 14 and 7 per side, at strides 4, 8, 16 and 32, just like a convolutional network.

Now the cost, which ties straight to Part C. Global attention, omega of MSA, is four h w C squared plus two times h w squared times C. h w is the number of tokens, and C is the channels. The second term compares every token with every token, so it grows with h w squared. Window attention, omega of W-MSA, replaces that with two M squared h w C. Each query only has 49 keys, so the cost grows linearly with h w. [69:08] Q9 · The idea: why detection needs a pyramid, and how FPN builds one
Why does detection need several scales? Classification gives one label per image. Detection must find every object and draw a box around it, and objects can be tiny or huge. A fine map, at stride 4, has one position per 4 by 4 pixels, so it keeps the detail needed for small objects. But it comes from early layers, so it knows little about what things are. A coarse map, at stride 32, has rich meaning but blurs small objects away. The FPN, from Lin and colleagues in 2017, gets the best of both. Each stage first goes through a one by one convolution, the lateral connection, so all levels have the same number of channels. Then, starting from the coarsest level, the map is upsampled by two and added to the lateral map of the next finer stage. Then a three by three convolution smooths each merged map, to remove the blocky artefacts of upsampling. So every output, P2 to P5, carries fine detail and strong meaning together. Swin's four stages plug straight into this. A plain ViT has only one stride 16 map, so methods such as ViTDet build a simple pyramid from that last map alone: two transposed convolutions upsample it to strides 4 and 8, and a pooling step gives stride 32. ViTDet found that the top-down connections are not even needed there.

[73:48] Q: What is an FPN, and how is Swin used for detection? · model answer
A model answer. Detection has to find objects of very different sizes, so it needs feature maps at several scales. An FPN, a feature pyramid network, takes the backbone's stages, applies a one by one lateral convolution to each so they share one channel width, and then goes top down: it upsamples the coarser map by two and adds it to the finer one, then smooths the sum with a three by three convolution. The two paths do different jobs. The top-down path carries strong semantic meaning from the deep, coarse stages down to the fine levels. The lateral connections bring in the high resolution detail, the exact edges and positions, that the coarse maps have lost. So every output, P2 to P5, knows both what the object is and where it is, and the detection heads run on every level. Swin's four stages, at strides 4, 8, 16 and 32, are exactly the pyramid an FPN expects, like a ResNet's C2 to C5, so they plug straight in, as in the Swin paper's Cascade Mask R-CNN. A plain ViT has one stride 16 map in every layer, and its global attention is quadratic in the number of tokens, which gets expensive at the large image sizes detection uses. So it needs an adapter, such as ViTDet's simple feature pyramid. Our own work stopped at the backbone: features only gave us the four maps, but we built no FPN and trained no detector.

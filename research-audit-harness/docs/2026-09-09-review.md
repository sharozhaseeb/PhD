# Research audit harness review

**Review date:** 9 September 2026.\
**Scope:** inspect the existing local checker, support the current Python optimization proposal, document actual behavior, and verify compatibility. This was not a new literature search or a runtime benchmark experiment.

## Findings and changes

| Finding | Effect before this review | Resolution |
|---|---|---|
| Finance flags were unconditional | A software-performance proposal had to assert irrelevant financial controls or fail | Added explicit `finance` and `software_performance` profiles; older packages default to finance |
| Three-year filename was mandatory | The user's two-year plan could not satisfy the layout convention directly | Accept a substantive two-year or three-year plan |
| Non-object JSON could crash | Syntactically valid arrays/scalars reached dictionary operations | Report a metadata failure and continue reporting other findings |
| Malformed CSV could crash or be misread | Extra row fields reached string operations; duplicate headers lost information | Reject overflow rows, blank/duplicate headers, and malformed quoting; report parsing/decoding failures |
| Search counts were only checked for nonemptiness | Arbitrary text or inconsistent counts could satisfy the completeness check | Require nonnegative integer triples with included <= screened <= returned; preserve warnings for unknown counts |
| Claim PASS text overstated evidence checking | Message implied evidence for established claims had been verified | State that only unsupported-status labels were checked |
| Auditing a missing directory created it | A failing audit could still create a new direction while writing reports | Print the failure report without creating the target |

The initializer now accepts `--profile` and shares the checker's protocol registry. It preserves its skip-existing behavior and explicit `--force` replacement. Existing finance requirements were retained.

## Verification

Executed on Python 3.12.10 using only the standard library:

```powershell
python -m unittest discover -s research-audit-harness/tests -v
python research-audit-harness/scripts/audit.py research-directions/llm-optimization-validation
```

All **18 tests passed**. Coverage includes both existing finance packages, the new software package and two-year plan, profile validation, literal booleans, malformed JSON/CSV, search-count validation, initializer default/profile/overwrite behavior, missing/file target behavior, strict/no-write exits, and report generation without changing source metadata.

## Remaining limits

The checker verifies conventions and declarations rather than their scientific validity. It does not verify citation contents, source access, unique record IDs, links, dates, all metadata fields, causal explanations, statistics, licensing, or the completeness of the literature search. It counts files and rows; it does not assess their substantive quality. `prohibited_claims` remains a documented policy rather than executable prose analysis.

Its output files are overwritten snapshots; history and signed evidence are not maintained. Some filesystem permission/output errors can still surface as exceptions. Extending error handling or metadata validation is possible if practical usage establishes the need, but should not be confused with scientific verification.

The separate runtime experiment harness described by the proposal remains unimplemented. Future work should begin with the bounded feasibility study and resolve dataset, workload, statistical, and budget choices before a main experiment.

The problem

Optimizers re-validate every candidate edit, and that work multiplies

The loop

Edit → build → run tests → run benchmarks → accept or reject. Repeated for every candidate, often dozens per task.

Who does it

LLM optimizers such as SemOpt and PerfAgent; harnesses such as SWE-Perf, GSO and FormulaCode.

SemOpt: full build, full tests and 6 performance runs per candidate, untimed.

Our question

Can deterministic reduction (incremental build, test and benchmark selection) cut that per-edit cost, and what can the cheaper check still see?

Motivating case: a networkx commit whose message claims bidirectional_dijkstra is “1.1× to 25× faster” (not re-measured). No benchmark in the project’s suite executes it.

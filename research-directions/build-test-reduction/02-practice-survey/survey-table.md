Status: draft 2026-11-21, built from critic-checked per-system notes (`per-system/*.md`, `critic-log-A..E.md`, final pass `critic-log-final.md`).

**Legend.** `[src]` read in source code or paper/docs by the researcher or critic. `[inf]` inferred by us from sources. `[unk]` not found (the note says where it looked). "—" means not applicable, never unknown.
**Citations.** Each cell's citation is the primary source copied from the per-system note: `file:lines @shortcommit` for code, `§x` / `App. x` for papers. The note link is in the System column. Where a note and a critic log disagreed, the note's corrected text is used. FIXED-PER-TASK = test set chosen once per task/problem/function/class; PER-EDIT = chosen from the candidate's own diff.
**Caveats carried over.** SWE-bench, Mercury, EvalPerf, COFFE, EffiBench-X, KernelBench paper claims were read via summaries only (see Discrepancies). Notes of one system may cite two commits (SWE-bench classic vs HEAD).

## Discrepancies and open items

Paper vs code conflicts
- **SWE-fficiency:** paper App. F.1 says evaluation runs perform no package installation; code puts `specs["install"]` in every perf/correctness script (5 installs per candidate on the CLI path) `test_spec.py:490-491`, `run_validation.py:560-572,943-958 @12d32a2`. Hard memory cap is 32g in code vs 16 GB in paper/README (16g is only a soft reservation). Docker-daemon pinning is described in the paper only (`scripts/vm/` not read). Legacy `run_evaluation.py` path differs from the leaderboard `swefficiency eval` path.
- **SWE-Perf:** CPU count differs: code gives 10 CPUs (2e9 nano_cpus x5, no cpuset) `docker_build.py:541-544 @9e8fed2`; paper says 1 core in collection and 5 in Phase 4/evaluation. Code search step 0.001 vs paper default 0.01. Repo count: README 12 crawled vs paper 9 in final dataset. A direct `mannwhitneyu` call at `check_validation_single_runs2.py:136` is dead code.
- **GSO:** paper defines success only as S >= p; code adds a >=1.1x geometric-mean gate over base and uses strict `>` `metrics.py:256-260 @32d78b3`. Per-instance install commands live in the HF dataset, not read [unk].
- **FormulaCode:** where the "roll back on failed correctness" rule is applied is [unk] (parser has no gate; Table 16 reports 47-56/108 rejected). The paper's "passes all tests the baseline passes" vs harness's changed-file filename heuristic (zero mapped tests -> exit 5). Holm-Bonferroni claimed in paper, not found in datasmith. Snapshot tests "return values" (§3.1) vs "local variables" (App. B.7). Agent timeout 6 h (paper) vs 3000 s (sample `task.yaml`).
- **COFFE:** per-measurement cap 5 s (paper §3.4) vs 50 s in code `evaluator.py:946 @7979acb`; "one process at a time" claim vs `-n` parallel containers; top-5 stressful-test selection step not found in repo [unk].
- **EffiBench:** timeout 10 s (paper) vs 5 s (code); NET is mean of ratios in paper but ratio of sums in script; `exit_status` quirk means failures rely on non-empty stderr `run_code.sh:39-48 @d29e43b`.
- **EffiBench-X:** ASan/`flags` registry field has no consumer, executed command is `g++ -std=c++20 -O2`; paper Table 13, App. A, App. C.2 not re-read (repeat study, limitations, cost are [unk]).
- **Mercury:** Beyond in code clips (max-runtime) in seconds, not runtime to [min,max] as paper Eq. 1; score uses `cases[0]` only vs paper K=5 `evaluator.py:461-486 @e885512`. Tests per task at evaluation [unk]. A newer `Mercury_Eval` repo was not read.
- **EvalPerf:** 118 tasks (docs) vs 121 (paper); paper says references profiled "multiple times" without a number, code default is 1 round `config.py:8 @26d6d00`.
- **SysLLMatic:** paper reports 2+5 measured runs and a final whole-app rebuild/re-measure (Alg. 1 l.19-21); code has `MEASURE/main.c` with 10 warm-up/20 runs, no performance gate, and `run_app_and_measure` has no call site. What `make compile`/`make measure` run is [unk] (template file missing at fd59fa4).
- **PerfAgent:** §III-D claims selection "without missing any correctness regressions", §VI says testmon covers Python only. No public code found [unk]. testmon DB build/refresh, full-suite fallback, per-candidate wall time, timing repeats/statistic and pinning are all [unk]. The "<3% variance" claim is unsupported by shown data.
- **ECO:** v1 (Mar 2025) and v2 (Sep 2026, retitled, renumbered) differ in section numbers and headline savings; test-selection mechanism ("all affected tests") is [unk]. No public artifact.
- **CodSpeed:** child-process and static-executable exclusion, 0-50% threshold range and "breach fails status check" are [unk] (not on the fetched docs pages).
